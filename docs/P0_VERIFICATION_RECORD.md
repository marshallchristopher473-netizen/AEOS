## 5. Accepted scope boundaries

These are known and deliberately left outside the P0 contract. P0 is closed
**for the tested contract only**, not for these.

1. **RLS measures the direct-database / PostgREST boundary.** The FastAPI path
   uses the service-role client (`BYPASSRLS`). It is protected by explicit
   application-layer tenant scoping, which M15 verifies, not by RLS.
2. **M16 is verified at source level.** The harness substitutes text in the
   frontend without building it.
3. **Artifact naming (PR #17 item 1).** CI uploads the mutation matrix as
   `mutation-matrix-${{ github.sha }}`. On `pull_request` events that resolves
   to the ephemeral merge commit, not the PR head. The fix is
   `${{ github.event.pull_request.head.sha || github.sha }}`. Still present at
   `b9c68aa`.
4. **`ai_recommendations` UPDATE/DELETE (PR #17 item 2)** are not exercised
   by any WHERE-less probe. `test_rls_enforcement.py` has no reference to
   the table at `b9c68aa`.
5. **The WHERE-less blind spot (PR #17 item 3)** was verified and closed for
   `students` only. The other `FOR UPDATE` policies were not swept.
6. **`JWKError` handling (PR #17 item 4)**: see F2.
7. **Vercel (PR #17 item 5)**: the deployment check stays red for the known
   project-configuration reason (`rootDirectory` not set). This record does
   not verify any deployment.
8. **No staging or production verification.** Nothing here proves behaviour
   against a real Supabase project, real authentication or a deployed
   frontend.
9. **Synthetic data only.** No real student information was used, and this
   record does not authorize its use. That still requires consent,
   agreements and the staging gate.
